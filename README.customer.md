# AISBench 网关

把 AISBench 的命令行测试包成网页操作：填模型服务地址，选数据集，点提交。
测试结果自动保存、可视化，多次结果可以叠在一起对比。

不需要懂 aisbench，不需要写配置文件，不需要联网。

---

## 一、安装

```bash
tar xzf aisbench-gateway-*.tar.gz
cd aisbench-gateway-*
./install.sh
```

安装脚本自动完成：检查环境 → 架构校验 → 配置模型目录 → 导入镜像 → 启动服务，
最后打印访问地址。

**要求**：只需要 **Docker**。

不需要 python3，不需要联网，不需要 pip 装任何东西 —— 网关本身就跑在
aisbench 容器里，用的就是容器自带的 Python。

**模型/tokenizer 目录是必填项**（随机数据集、GSM8K 前缀数据集、sharegpt 都需要它）。
安装时会提示输入，填模型所在目录，或装了多个模型的**父目录**（如 `/data/models`，
网关会自动扫描其中的模型文件夹，页面上按名字选择）。也可以非交互安装：

```bash
./install.sh --yes --tokenizer /data/models
```

脚本可以重复执行：中途出错修好后再跑一次即可，已完成的步骤会自动跳过
（已配置的模型目录会保留，回车确认即可）。

### 分片包

如果拿到的是 `.part-aa`、`.part-ab` 这样的分片，先合并再解压：

```bash
cat aisbench-gateway-*.tar.gz.part-* > aisbench-gateway.tar.gz
sha256sum -c SHA256SUMS      # 可选，校验完整性
tar xzf aisbench-gateway.tar.gz
```

## 二、使用

浏览器打开 `http://<本机IP>:8080`（安装完会打印具体地址）。

### 新建测试

1. **Base URL** — 模型服务地址，如 `http://192.168.1.10:8000`
   （带不带 `/v1` 都行，网关会自动处理）
2. **接口类型** — 按你的服务选：`chat/completions` 还是 `completions`，流式还是非流式
3. **模型名** — 留空会自动探测
4. **API Key** — 服务需要鉴权时填，不需要就留空
5. 选数据集和参数，点「提交测试」

### 精度测试

模式切到「精度测试」，选数据集，提交。跑完在详情页看各数据集得分。

「样本数上限」可以只跑前 N 条，用于快速验证链路。注意部分数据集
（如 HumanEval、MBPP）的评分要求全集，截断会导致评分失败，此时留空即可。

### 性能测试

选数据集，设定并发，提交。跑完得到吞吐和逐请求分位指标
（E2EL / TTFT / TPOT / ITL 的均值、P75/P90/P99 等）。

**输入/输出长度**用「随机数据集」时可以直接指定（不需要下载数据）：

- 「输入长度下限/上限」控制每条请求的输入长度。**两个填相同值就是固定长度**；
  填不同值则在该区间内随机。
- 「输出长度上限」控制每条请求的输出长度，同理。

> 实测的 token 数会比这里填的**略多几十个**，因为 aisbench 套 chat 模板时会加
> 角色标记等。比如填 512，实测输入 token 通常落在 560 左右。
>
> 另外：选随机数据集时，上方那个「最大输出长度」是**不生效**的
> （随机数据集的每条请求自带输出长度，优先级更高），界面里会自动置灰并说明。

**并发梯度扫描**：把「并发档位」填成 `1,8,16,32,64`，网关会逐档跑完，
画出「并发-吞吐」「并发-时延」曲线，用来找吞吐拐点。

### 指定长度 / 测 prefix cache（合成数据集）

数据集选「**GSM8K 前缀数据集**」，会从内置的 GSM8K 里取语料，合成出
**长度由你指定**、**前缀按比例复用**的数据集。两个用途：

- **长上下文压测**：真实数据集的 prompt 长度是固定的，压不了 32k/128k。
  这里把长度填成你要的值就行。
- **测 prefix cache 命中下的性能**：填「前缀比例」，比如 50%，
  那么每条请求的前一半内容在请求之间是相同的，能命中 KV cache。

主要参数：

| 参数 | 说明 |
|---|---|
| 输入长度 | 定长，或选均匀/高斯分布（长上下文常用「8k~128k 均匀」这种） |
| 数据条数 | 数据集行数，也就是请求数（会覆盖上面的「请求数」） |
| 前缀比例 | `50%` 或 `0.5` 都行。0 表示只按长度合成、不做前缀复用 |
| 前缀个数 | 前缀的种类数，每条数据轮流用其中一种 |
| DP 域数 | 预热阶段的并发。有几个 DP 域就填几 |
| 先预热前缀 | 建议勾上，见下 |

**预热是干嘛的**：各 DP 域的 KV cache 不共享，如果直接跑正式数据集，
每个域都得从零算一次前缀，测出来的命中率会被稀释。勾上后会先拿前缀单独跑一遍
（并发 = DP 域数），让每个域都吃到前缀，再跑正式测试。跑完**只有正式测试的结果入库**。

**采集实际命中率**：勾上后（默认勾）会在压测前后各读一次被测服务的 `/metrics`，
算出**真实的** KV cache 命中率，结果在任务详情页里，也会并进结果数据，
可以在「结果对比」页和吞吐/时延放一起看。

- 需要被测服务是 vLLM 并且暴露了 `/metrics`（自检：
  `curl http://<ip>:<port>/metrics | grep prefix`）
- 默认查的就是上面填的 Base URL。**PD 分离**的部署要额外在 `config.ini` 里配：
  ```ini
  [metrics]
  pods = 10.0.0.11:8000, 10.0.0.12:8000    # 各 P 节点的 IP 和对应 DP 域端口
  ```
  改完 `./stop.sh && ./start.sh`
- 命中率按**每个 DP 域**分别列出再合计。分域很有用：如果某个域明显偏低，
  说明预热没覆盖到它
- 读不到不影响测试：任务照常跑完，日志和详情页里会说明原因（比如地址不通、
  服务没有这个接口），只是不显示命中率
- 如果显示"指标没有增长"，说明请求没打到你查的这个服务 —— 检查一下
  metrics 端点是不是被测服务本身

> **并发扫描时请勾上「先预热前缀」。** 各档位是串行跑的，KV cache 会从上
> 一档留到下一档。不预热的话，第一档要付冷启动的代价、后面几档白捡前面积累的
> 缓存，测出来的命中率就变成"这一档排在第几个"的函数，档位之间没法比。
> 实测同一份数据（设定 50%）：不预热时两档分别是 39% 和 60%，
> 勾上预热后各档都稳定在设定值附近。

**为什么实测长度和我填的不一样**：

- 数据集本身是准的（填 512，数据集里就是 512），生成时会回读校验并在详情页显示实测值
- 但请求发出去时会**多出约 50 个 token** —— aisbench 套 chat 模板会加角色标记。
  比如数据集是 512，服务端实际收到 564
- 另外长文本有 ±1~2% 的抖动，这是 tokenize↔decode 往返导致的有损误差

生成需要时间，和「输入长度 × 条数」成正比（4096 × 160 条约 15 秒，128k 会明显更慢）。
进度会实时打在任务日志里。同样的参数再提交一次会直接复用上次生成的数据集，不重新生成。

> 合成数据集的答案字段是占位符，**只能做性能测试**，精度得分没有意义。

需要用到的 tokenizer 见下一节。

### 结果对比

「结果对比」页勾选多条运行记录，叠图对比。颜色跟随记录本身，
取消勾选不会让其余曲线变色。

### 备注（区分多组参数）

跑多组参数对比时，光看自动生成的标题分不清哪条是哪条。**备注**就是给这个用的：

- **提交前填**：表单最下面有「备注（可选）」，比如「Qwen3-32B / 4k 输入 / 并发 32」
- **跑完再补**：任务列表每行的「备注」按钮，或进详情页在顶部输入框里改
- 备注会**盖过自动标题**，显示在任务列表和结果对比的图表里；
  自动标题降级成下面的一行小字，两组信息都还在
- 留空即清除

**并发扫描**：备注写在父任务上，各个档位自动沿用，并在图表里带上并发数
（如「A组：4k/50% · 并发 8」），这样同一组的不同档位也能区分。
改父任务的备注，各档位会立刻跟着变。

## 三、常用命令

```bash
./start.sh                      启动（后台常驻，开机自启）
./stop.sh                       停止（保留容器，下次启动更快）
./stop.sh --purge               停止并删除容器（数据不受影响）
./status.sh                     查看状态与诊断信息
./run.sh                        前台运行，实时看日志（排障用）
docker logs -f aisbench-gateway 看实时日志
```

## 四、关于 tokenizer

随机数据集（synthetic）、sharegpt 和合成数据集（GSM8K 前缀数据集）需要
一个**本地 tokenizer** 才能跑，aisbench 镜像里不带任何 tokenizer。

**安装时已经强制配置过一次**（填的是模型目录或装了多个模型的父目录）。
页面上的「模型 / Tokenizer 目录」按以下方式填写：

- 只填**模型文件夹名**，如 `Qwen3.5-35B-A3B`——输入框有下拉，列出的是
  网关扫描到的所有模型目录（HuggingFace / ModelScope 下载的文件夹都认识），
  提交时自动拼成完整路径
- 也可以填完整路径（容器内路径；配置的目录按原路径只读挂进容器，
  所以容器内路径与宿主机相同）

事后想改目录：编辑 `config.ini` 里的 `aisbench.tokenizer_dirs`（多个用逗号分隔），
改完执行 `./stop.sh && ./start.sh` 重建容器。

另外也可以把 tokenizer 目录直接放进 `data/models/` 下，页面上填
`/work/models/<目录名>` 引用，随数据目录一起搬走。

其余数据集（gsm8k / mmlu / ceval / math 等）不需要 tokenizer。

## 五、数据集

交付包内置了这些常用数据集，开箱即用：

| 数据集 | 用途 |
|---|---|
| gsm8k | 小学数学应用题 |
| mmlu | 英文综合知识 |
| ceval | 中文综合 |
| cmmlu | 中文综合 |
| math | 数学竞赛 |
| gpqa | 研究生级问答 |
| humaneval | 代码生成 |
| mbpp | Python 编程 |

另外还有两个不需要下载的：

| 数据集 | 用途 |
|---|---|
| 随机数据集 | 随机生成指定长度的输入输出，纯压测首选 |
| GSM8K 前缀数据集 | 从 GSM8K 合成指定长度 + 前缀比例的数据，见上文 |

「数据集」页里还列出了其他数据集，需要联网下载后才能使用。
下载地址是公开的 OSS，若客户机器不能上外网，可以先用能上网的机器下载好，
把解压后的目录拷到 `data/datasets/ais_bench/datasets/` 下。

合成出来的数据集会存在 `data/generated/` 下，每个参数组合一个目录，
可以直接拷走复用。

## 六、排障

先跑 `./status.sh`，它会一次性打印网关进程、端口、容器、镜像、数据集、
架构等状态和最近的日志。

| 现象 | 处理 |
|---|---|
| 打不开页面 | `./status.sh` 看容器是否在跑、端口是否被占用 |
| 右上角显示「服务异常」 | 点那个标签可以重新自检并看到具体问题；重建容器用 `./stop.sh --purge && ./start.sh` |
| 任务一直「排队中」 | 前面有任务卡住了。网关有看门狗会自动终止卡死任务；也可以手动点「取消」 |
| 任务失败提示找不到数据集 | 该数据集未下载，去「数据集」页下载（需联网） |
| 提示需要 tokenizer | 见第四节 |
| 合成数据集提示「前缀个数超过 GSM8K 语料条数」 | GSM8K 有 1319 条语料，前缀池要求每条互不相同，把「前缀个数」调到 1319 以内 |
| 合成数据集任务跑了很久还在「运行中」 | 长上下文生成很慢（128k × 大条数要几分钟），看任务详情里的日志有实时进度。同参数第二次提交会复用 |
| 合成数据集长度和填的不一致 | 见「指定长度 / 测 prefix cache」一节：请求会比数据集多约 50 token 的 chat 模板开销 |
| 详情页没有「Prefix cache 命中率」 | 一般是被测服务没暴露 `/metrics`。详情页和运行日志里会写明原因 |
| 命中率显示「指标没有增长」 | 请求没打到你查的那个服务。检查 metrics 端点和被测服务是不是同一个实例 |
| 命中率明显低于设定的前缀比例 | 没勾「先预热前缀」，或 DP 域数填小了（每个域都要预热到）。看详情页里各 DP 域分别是多少 |
| 提示 base_url 不能为空 | 没填模型服务地址 |
| 任务失败提示 `Cannot connect to host ...` | 模型服务地址不对，或服务没起，或网络不通。先在服务器上用 curl 试一下那个地址 |
| 任务卡住不动 | 看门狗会在超过 `stall_timeout`（默认 900 秒）无输出时自动终止；可在 `config.ini` 调小 |
| 提示「这个交付包是 arm64 架构的，而本机是 amd64」 | 交付包里的镜像是**单平台**的，和本机架构不符，容器起不来。换对应架构的机器，或索取对应架构的交付包 —— 不是配置问题 |
| 任务偶发卡死不动 | 已知问题，原因未定。看门狗会在 `stall_timeout`（默认 900 秒）后自动终止；先把样本量调小重试 |

配置文件是 `config.ini`，改完需要 `./stop.sh && ./start.sh` 生效。

运行数据都在 `data/` 目录下（测试产物、数据集、tokenizer、数据库），
整个目录可以直接拷走备份或迁移。

> 注意：配置文件和数据都在**宿主机**上，容器是只读挂载代码、读写挂载数据目录。
> 所以升级代码或改配置都不需要动镜像。

## 七、目录说明

```
install.sh / start.sh / stop.sh / status.sh     运维脚本（纯 bash + docker）
run.sh / lib.sh                                 前台运行 / 脚本共用函数
config.ini                                      配置（端口、镜像名、tokenizer 等）
README.md                                       本文档

gw/         后端服务代码  ┐
static/     前端页面      ┘  只读挂载进容器 → /gateway

images/     aisbench 镜像文件
seed/       预置数据集

data/       运行时数据        读写挂载进容器 → /work
            （配置、产物、数据集、tokenizer、数据库、合成数据集）
```

容器启动命令大致是这样，排障时可能用得上：

```bash
docker run -d --name aisbench-gateway --network host --restart unless-stopped \
  -v "$PWD:/gateway:ro" -v "$PWD/data:/work" \
  -w /gateway -e AIS_BENCH_DATASETS_CACHE=/work/datasets \
  <镜像> python3 -m gw.main
```
