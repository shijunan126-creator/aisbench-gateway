前缀比例指每条请求的前多少 token 会在请求之间复用（比如 50% 表示前一半能命中 KV cache）。前缀个数是前缀的种类数，每条数据轮流用其中一种。
预热会先拿前缀单独跑一遍（并发 = DP 域数，不限速），让每个 DP 域的 KV cache 都吃到前缀，再跑正式数据集 —— 各 DP 域的 cache 不共享，不预热的话命中率会被稀释， 测不到稳态。输出长度用上面的「最大输出长度」。

实测长度会比这里填的略多：一是 tokenize↔decode 往返有 ±1~2% 误差， 二是 aisbench 套 chat 模板会加角色标记（本机实测约 50 token）。 比如填 512，数据集里确实是 512，请求发出去时是 564。

采集实际命中率会在压测前后各读一次被测服务的 /metrics， 用增量算出真实的 KV cache 命中率（对比页里可以和吞吐一起看）。 需要服务是 vLLM 且暴露了 /metrics；读不到只是不显示， 不会让任务失败。查哪个地址默认就是上面的 Base URL，PD 分离时在 config.ini 的 [metrics] pods 里配各个 P 节点。
